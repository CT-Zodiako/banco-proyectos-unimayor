# UNIMAYOR research search tools

Monorepo for the search tools of the Laboratorio de Física y Sistemas Embebidos,
Institución Universitaria Colegio Mayor del Cauca. Web apps live in `apps/` and data pipelines in `pipelines/`.

| Tool | Path | What it does | Stack |
|---|---|---|---|
| Project bank | [`apps/banco-proyectos`](apps/banco-proyectos) | Catalog of 236 projects in 23 areas (the original 100 IoT projects plus new areas), filters by area and sector, project detail; also hosts the journal finder and the event finder as React routes | React 18, Vite 5, Tailwind 3, React Router, deployed on Railway |
| Where to publish | [`pipelines/donde-publicar`](pipelines/donde-publicar) | Indexed (SCImago Q1–Q4), no-APC, free-to-read journals (DOAJ) for each project | React route `/donde-publicar` in the project bank (`src/pages/DondePublicar.jsx`); Python 3 pipeline that only generates JSON data in `apps/banco-proyectos/public/data` |
| Event finder | [`pipelines/eventos`](pipelines/eventos) | Calls for papers and events to attend (WikiCFP, ccf-deadlines, Devpost and a manual file of local events) | React route `/eventos` in the project bank (`src/pages/Eventos.jsx`); Python 3 pipeline that only generates JSON data in `apps/banco-proyectos/public/data` |

All three front ends are React and ship in the project bank build (`apps/`). The data pipelines live in `pipelines/`:
`pipelines/donde-publicar` and `pipelines/eventos` only hold the Python data pipelines (and their tests and inputs) and
generate the JSON into `apps/banco-proyectos/public/data`; the generated JSON is committed.

## Project bank

```bash
cd apps/banco-proyectos
npm install
npm run dev        # local development
npm run build      # production build (dist/)
```

Projects are stored in `src/data/baseProjects.js` (original 100) and `src/data/projects/<area>.js` (new areas);
`npm test` validates them and runs two suites: `npm run test:unit` (`node --test "tests/*.test.mjs"`, pure logic) and
`npm run test:dom` (Vitest + jsdom + Testing Library, `tests/dom/*.test.jsx`: the real `<App/>` is driven through the UI with
`fetch` mocked to serve small fixtures instead of `public/data/*.json`; covers the project panel, the legacy redirects and the
finder filters). `npm run lint` checks the code and the tests (ESLint, config in `.eslintrc.cjs`). The journal finder and the event finder are React routes of this app, `/donde-publicar` and `/eventos`
(`src/pages/DondePublicar.jsx` and `src/pages/Eventos.jsx`), and read the JSON generated by the Python pipelines
(`public/data/publicar-data.json`, `publicar-catalog.json` and `eventos.json`). These files are not bundled in the JS:
Vite copies `public/` to the site root and the app fetches them at runtime from `/data/<file>.json` (`src/lib/data-loader.js`,
one shared download per file); Nginx compresses them with gzip and revalidates them, since the weekly refresh replaces them. Each project links to both: "¿Dónde publicar este
proyecto?" (`/donde-publicar?p=<id>`) and "¿A qué eventos ir?" (`/eventos?p=<id>`, events ranked by
estimated affinity with the project). The old URLs `/donde-publicar/index.html?p=<id>` and `/eventos/index.html?p=<id>`
still work: the router redirects them to the new routes keeping the same project preselected. The project page also
opens both finders in a slide-over panel (Revistas | Eventos tabs, `?panel=revistas|eventos`, `src/components/proyecto-panel/`)
that reuses the same components and logic with the project preselected, so the project can be read without leaving it;
"Abrir en la página completa" in the panel goes to the two pages above, which are unchanged. Deployment: see Railway
deployment below.

## Saved opportunities

The project bank's **Mis oportunidades** page (`/oportunidades`) gathers events and journals saved from their cards. Favorites are kept only in the current browser's local storage, are not synchronized between devices, and can be lost when browser data is cleared. Saved events can download calendar files for their start and submission deadline when those dates are known; preparation checklists offer guidance for events and journals, link to the saved official source when available, and are not persisted. From that page, export a JSON backup of favorites, statuses and notes, or preview a backup before importing it. Import keeps existing records unchanged when the same type and ID already exist, including their notes and status; malformed files are rejected. The JSON file contains personal notes, so store it securely. Official sources remain authoritative.

## Railway deployment

The private GitHub repository `CT-Zodiako/banco-proyectos-unimayor` is connected to the
Railway project and service `banco-proyectos-unimayor` (production, branch `master`).
Pushes to `master` trigger a deployment using the root `Dockerfile`.

The multi-stage image builds the project bank (`npm ci` and `npm run build` in `apps/banco-proyectos`) and serves
`dist/` with Nginx; the journal and event pages are part of that build, so no other folder is copied. `PORT` defaults to
`8080`; every path that is not a file, including `/donde-publicar`, `/eventos` and their old `/index.html` URLs, falls
back to `index.html` and the React router handles it.

Nginx (`deploy/default.conf.template`) enables gzip for JSON, JS, CSS and HTML, caches the hashed `/assets/` for a year
(`immutable`), makes the browser revalidate `/data/*.json` and `index.html`, and answers a missing `/data/*` file with 404
instead of the single page app fallback.

```bash
docker build -t publicaciones .
docker run --rm -p 8080:8080 publicaciones
```

Public URL: https://banco-proyectos-unimayor-production.up.railway.app
No Python pipeline runs at deploy time: the journal and event data are generated beforehand and committed.

## Automatic data refresh

The workflow [`.github/workflows/actualizar-datos.yml`](.github/workflows/actualizar-datos.yml) refreshes the
JSON data of the journal finder and the event finder every Monday at 09:00 UTC (04:00 in Colombia). To refresh on demand, open
**Actions → Actualizar revistas y eventos → Run workflow** on GitHub.

Each run:

1. Exports the bank projects to `pipelines/donde-publicar/data/projects.json`.
2. Journals: runs the Python tests and the page-logic tests (`publicar-*.test.mjs`), downloads DOAJ, rebuilds
   `publicar-data.json` and `publicar-catalog.json` with the SCImago CSV stored in the repository, and checks them with
   `publicar-data.test.mjs`.
3. Events: runs the Python tests and the page-logic tests (`eventos-*.test.mjs`), rebuilds `eventos.json` with
   `--require-all-sources` (WikiCFP, ccf-deadlines, Devpost and the manual file), and checks it with
   `eventos-data.test.mjs`.
4. Commits whatever was refreshed (`pipelines/donde-publicar/data/projects.json` and the three JSON files in
   `apps/banco-proyectos/public/data`) to `master` (`chore(data): refresh journals and events <date>`), which makes
   Railway redeploy.

An app whose tests, download or build fails keeps its previous data, and the run ends as failed, so GitHub e-mails
the owner. A source outage never publishes an emptier catalog: the journal build refuses an empty DOAJ/SCImago join,
and the event build refuses to write when any public source fails.

**Once a year, update SCImago by hand.** SCImago blocks scripted downloads and publishes a new ranking yearly.
Download it as described in [`pipelines/donde-publicar/README.md`](pipelines/donde-publicar/README.md#regenerate-the-data),
replace `pipelines/donde-publicar/data/raw/scimago/scimagojr.csv`, commit it, and run the workflow. The journal page shows
the dates in use ("DOAJ: 2026-11-09 · SCImago: edición 2025").

## Where to publish

See [`pipelines/donde-publicar/README.md`](pipelines/donde-publicar/README.md). Run its commands from that folder:

```bash
cd pipelines/donde-publicar
python3 -I -m unittest discover -s tests -t .
python3 -E -m pipeline.build      # writes publicar-data.json and publicar-catalog.json in apps/banco-proyectos/public/data
```

The DOAJ download in `pipelines/donde-publicar/data/raw/doaj/` is not versioned. The SCImago CSV in
`pipelines/donde-publicar/data/raw/scimago/` is versioned so the weekly workflow can use it.

## Event finder

See [`pipelines/eventos/README.md`](pipelines/eventos/README.md). Run its commands from that folder:

```bash
cd pipelines/eventos
python3 -I -m unittest discover -s tests -t .
python3 -E -m pipeline.build      # downloads the sources (about 4-5 minutes) and writes apps/banco-proyectos/public/data/eventos.json
```

Local Colombian events go in `pipelines/eventos/data/manual-events.json`. Downloads are cached in
`pipelines/eventos/data/raw/` (not versioned).
